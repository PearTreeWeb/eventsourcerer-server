Production Readiness Checklist

This checklist outlines critical and recommended steps before deploying EventSourcerer to a production environment.

1. Security & Access Control

  • Restrict Administrative Routes: Currently, many dashboard and tool routes lack explicit #[IsGranted] attributes. Update security.yaml or add attributes to App\Controller\Tool\All, App\Controller\SimpleServerEvent\*, and other sensitive controllers.
  • Enable App-level CSRF: Verify all state-changing forms (POST) use Symfony's CSRF protection (mostly enabled by default).
  • Production Secrets: Ensure APP_SECRET and DATABASE_URL are set via environment variables, not hardcoded in .env.
  • SSH Key Rotation: Establish a policy for rotating the public SSH key used for personal data encryption.

2. Infrastructure & Scalability

  • Event Loop Optimization: The socket server is limited by stream_select() (1024 FD limit). Install php-ev or php-uv extension for high-concurrency production use.
  • Persistent Cache: Switch from cache.adapter.filesystem to cache.adapter.redis in cache.yaml for better performance and shared state between multiple web/worker instances.
  • Doctrine Cache: Verify when@prod settings in doctrine.yaml use the doctrine.system_cache_pool.
  • Messenger Workers: Configure async and projections workers as supervised processes (e.g., using Systemd or Supervisor).

3. Stability & Observability

  • Logging: Review EncryptPersonalDataHandler and Controllers. Replace generic catch (\Throwable) blocks with proper logging (LoggerInterface) before failing silently or showing generic flashes.
  • SSE Isolation: The NewEvents SSE controller currently uses a shared cache key for maxSequenceReceived. This should be isolated per session or client to avoid race conditions and incorrect event delivery.
  • Database Indexing: Ensure stream_event table has optimized indexes on stream_id and sequence (already largely handled by migrations, but worth a final check).

4. Cleanup & Maintenance

  • Remove Generate Tools: Disable or password-protect app:generate:events in production to prevent accidental data flooding.
  • Tombstone Process: Verify the app:tombstone:events command is scheduled if data retention policies are in place.
  • Unimplemented TODOs: Address "TODO" markers in src/Repository/Postgres/PostgresNonEncryptedStreamEvents.php and Form types.
